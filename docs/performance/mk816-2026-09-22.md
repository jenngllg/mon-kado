# MK-816 local performance evidence — 2026-09-22

Validation is complete for the requested profiles. These are local Docker
measurements, not a claim that every workload meets its target or that VPS
throughput is guaranteed. The associated JSON contains the bounded evidence.

## Environment

Docker Desktop, Linux cgroup v2, 12 logical host CPUs, 8,286,515,200 bytes of VM
memory. The four application services share 805,306,368 bytes (768 MiB), zero
swap and CPU quota `100000 100000`. Ten separate k6 containers are outside this
budget. The API runs in Production; the Worker runs in Local with email disabled.
All data is synthetic: 100 members, 500 lists, 10,000 wishes and 200 initial images.
No VPS, production credentials or external provider was contacted.

## Image limitation: genuine resource failure

Run `mk816-38be832056ae`, revision `0df15206ac3cc3a12c1332e5455549da5b25f2f7`:
the 40 MP gift-image case produced one recorded OOM kill and an API exit. The
supervisor stopped the generators. There were 185 measured background requests,
35 unexpected failures after the outage, and no 429s or dropped iterations.
The database still contained 100 members, 500 lists, 10,000 wishes, 202 images
after fixture mutations and zero over-reserved wishes. No restart was attempted.

The failing case included a single upload followed by a concurrent pair; this
run did not retain the sub-step, so it does not prove which of those two phases
exceeded memory. Subsequent harness reports preserve completed measurements and
the exact concurrency of a failed image case.

The current processor decodes full-resolution pixels before resizing. A 40 MP
RGBA bitmap alone represents about 160 MB of native pixel memory, beyond the
managed GC heap budget. This is a plausible contributor, not a completed memory
profile or a proved sole cause. Changing the processor, admitted dimensions,
concurrency policy or VPS size requires a separate decision. No production
limit or acceptance threshold was changed to hide this failure.

## Harness corrections and review

- Corrected terminal k6 iteration accounting; an earlier 305/300 request smoke
  was explicitly incomplete, not accepted.
- Corrected the BusyBox TLS probe option; its false unavailability result was
  not attributed to application performance.
- Used API-issued signed/versioned URLs when verifying downloaded images.
- Preserved private fixture permissions on POSIX and Windows; generators on
  Linux use the fixture owner's UID, without DAC-bypass capabilities.
- A pre-existing monitoring OOM exercise now touches allocated pages so lazy
  allocation cannot falsely avoid the expected OOM event.

The stress result is intentionally incomplete because the plan requires missing
samples to invalidate a campaign. Long campaigns are never retried automatically.
The CI smoke and static/security checks for the reviewed harness are green; the
Sonar quality-gate result is tracked separately by the PR and must be green before
merging.
